I learned about three types of scans that an attacker might conduct to a network. These are:

```
**-sT** - a full scan, these scan completes the full TCP handshake
```
**SYN, SYN ACK, ACK** and then the termination with **RST ACK or FIN ACK**, although there are times when the dropping/closing of the connection isn't captured so we don't always rely on those packets`  
also, when a port of a target that is closed is being scanned, the target replies with **RST ACK** `
lastly, an initial packet from the target usually has a window size of greater than 1024 

initially we can use:
`tcp.flags == 2 and tcp.window_size > 1024` to look for IP addresses that are repeating and is scanning the network. Once we can locate that, we can look specify the IP address of the scanner and tuning our filter to only see the handshakes that are related to that IP by:

`ip.addr == [scanner IP] and 
`((tcp.flags == 2 and tcp.window_size > 1024) or tcp.flags == 18 or tcp.flags == 16 or tcp.flags == 20 or tcp.flags == 17)  
this eliminates the noise from other TCP protocols, and focuses on one IP and the entirety of the whole handshake, whether it's open or not. 


-sS -this on the other hand, is an example of a stealth or a speed scan. It just sends the first part of the handshake which is SYN to the target, wait for the target to respond with a SYN ACK. After it receives both indicators, it terminates the connection with RST. This means that the port was open.
If the target's port is closed, the target's port send a RST ACK.
these scans usually have a window size less than or equal to 1024

for this scan we can filter it out by using
`tcp.flags == 2 and tcp.window_size <= 1024`
look for the IP that's initiating these handshakes and then filtering it out by using 
`ip.addr == [scanner IP] and ((tcp.flags == 2 and tcp.window_size <= 1024) or tcp.flags == 18 or tcp.flags == 4 or tcp.flags == 20` 

we can then try to correlate again and reconstruct the conversations so we can see all the successful scans that happened.

-sU, is another type of scan that uses UDP. Since this is not a connection oriented protocol it doesn't rely on a handshake, and instead relies on the unreachable destination and port that the target might send if a port is closed. The target will send a ICMP Type 3 (Destination unreachable) Code 3 (Port Unreachable) 

we can start filtering it by using:
`udp`, or even using `(icmp.type == 3 and icmp.code == 3)`then adding columns like source and destination IP along with ports to see if a singular IP is trying to send to multiple IPs. and if an ICMP response is being sent to 1 IP by multiple IPs 
After that we can further eliminate noise by 
`ip.addr == [scanner IP] and (udp or (icmp.type == 3 and icmp.code == 3))`

or we can even use 

`ip.dst == [scanner IP] and (icmp.type == 3 and icmp.code == 3)`

to filter out responses from the target, and is headed through the target IP.
