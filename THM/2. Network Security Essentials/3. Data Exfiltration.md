# Data Exfiltration through DNS Tunnelling 

- Exfiltration that is compromising the trust for DNS, and encodes it within queries and responses. 
- DNS uses UDP (mostly) on port 53 for queries and responses; TCP is used for zone transfers or large responses.

**Indicators of attack for DNS Tunnelling**
- DNS queries sent to a single external domain
- Long subdomain labels or long query names 
- High entropy or Base62/64 patterns 
- Rare record types (TXT, NULL), or many large TXT responses 
- Unusual response behavior: frequent NXDOMAIN (exfil by query without answering), or large TCP UDP fragments 
- Queries at regular intervals 

# Data Exfiltration through FTP 

How attackers use FTP for exfiltration
1. Use of legitimate users 
2. Through compromised credentials 
3. Use of non-standard ports 

Indicators of attack: 
1. USER and PASS commands 
2. STOR (upload) and RETR (download commands), repeated or large transfers
3. Large data connections to unusual external IPs
4. Out of cycle logging
5. Data channel openings on ephemeral ports (PASV)

Filters we can use for Wireshark: 
1. STOR (upload)
2. RETR (download)
3. ftp contains ".file extensions"
4. frame.len > 90 large payload size 
5. ftp.request.command == "USER"/"PASS" and ftp.request.arg == "user"
	1. Singles out requests that came from User: user 
6. ftp.response.code == 530
7. (ftp.response.code == 530) and (ftp.response.arg contains "username") [lists target username]
8. (ftp.request.command == "PASS") and (ftp.request.arg == "password")
9. ftp.response.code == x1x,x2x,x3x series
10. ftp.response code == 230 (user login)
11. 231 (logout)
12. 331 (valid username)
13. 430 (invalid username or password)

# Data Exfiltration via HTTP 

Moving data out using HTTP 

Why it matters?
1. Traffic blends in 
2. Helps trace attacker activity post-compromise 

How adversaries use HTTP?
- **POST uploads to external servers**: Bulk data is sent to attacker-controlled hosts or cloud storage in POST request bodies.
- **GET requests with encoded data**: Attacker squeezes small chunks into query strings or path segments (useful for low-and-slow exfiltration).
- **Use of common services / CDN**: Exfiltration disguised as uploads to popular services or attacker-controlled subdomains under reputable domains.
- **Custom headers**: Data placed in headers (e.g., `X-Data: <base64>`) may bypass some string-based DLP.
- **Chunked transfer / multipart**: Large payloads split into multiple requests to avoid size thresholds.
- **HTTPS/TLS tunneling**: The encrypted channel hides the payload; detection requires TLS inspection, SNI analysis, or metadata-based detection.
- **Staging via cloud services**: The attacker uploads to Dropbox/GitHub/Gist and then fetches externally.

**Indicators of Attack** (IoA)
1. HTTP post to external hosts 
2. HTTP requests to domains with low reputation/rarely seen in traffic 
3. Small requests to the same hosts 
4. Chunked/multipart transfers 

Wireshark filters 
1. http.request.method == "POST" and frame.len > specify_length
2. Inspect traffic 
3. Inspect IP addresses 


# Data Exfiltration via ICMP 

Actors encode data through (echo, request/reply, timestamp, info)

**Common Techniques**
1. ICMP echo (type 8)/ reply (type 0) - places encoded (base64/hex) chunks of files inside ICMP
2. Custom ICMP types/codes - using uncommon ICMP types or non-zero codes to avoid signature based detections 
3. Fragmentation and assembly - split across packets 
4. Encryption/Obfuscation - Encrypting payload (base64) to random data 

**Indicators that something might be malicious**
1. ICMP sessions to external hosts 
2. Large ICMP payloads frequent ICMP payloads
3. ICMP payloads that contain high-entropy data (random)
4. ICMP that is not followed by legitimate traffic 

**Indicators of Attack in Wireshark**
1. Single host sending ICMP requests to an external IP 
2. Large frame.len or icmp.payload > 64 bytes
3. ICMP type/code unusual values 8 0 and 0 0 are normal 
4. Regular timing 
5. Multiple packets from the same src/dst 

In ICMP, the first number is **Type**, the second is **Code**.

```
Type 8, Code 0 = Echo Request
```

This is the “ping request”:

```
Are you there?
```

```
Type 0, Code 0 = Echo Reply
```

This is the “ping response”:

```
Yes, I’m here.
```

Sent back by the target.

# Typical pattern:

```
Victim -> Attacker: ICMP Type 8 Code 0 Echo Request with hidden data
Attacker -> Victim: ICMP Type 0 Code 0 Echo Reply
```

The hidden/exfiltrated data may be inside:

```
the Echo Request payload
the Echo Reply payload
or both
```
