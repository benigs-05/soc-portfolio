
- A CDN acts as an intermediary between visitors and the websites’ original servers. It can provide **faster content delivery, reduced server load, and protection against attacks such as DDoS**.
- User triggers cache check
- Each cache has its own TTL
- If you look up a shared CDN IP in VirusTotal, its **Relations** tab may show many domains that have resolved to that IP.
# A website without a CDN 
Example: 

Company owns company.com. 
- Website runs in Singapore.com 
- Stores the website's files and run its applications 
- We call this the origin server since this is where it builds the source of its contents 

# Now that same website but with a CDN 
- A CDN operates servers in many places 
- These are called edge servers 
	- They serve content closer to visitors 

CDN is placed in front of the origin server 

```
Your browser → CDN edge server → Company's origin server
```

- The CDN sits in front of it, delivering content on its behalf 

# How the company connect its website 
Usually:
1. Adds company.com to its CDN account 
2. Tells the CDN where the origin server is 
3. Configures HTTPS certificates and caching rules 
4. Changes DNS so visitors can reach the CDN instead of going directly to the origin 
You still type https://company.com. 
```
Before the CDN 192.1.0.0

After CDN company.com -> 198.51.100.20
CDN Confiuration -> 192.1.0.0
```
# How different websites share a CDN IP

- IP address is not necessarily one website. 
- The browser's request also identifies the website's hostname compay.com
- CDN uses that information and its configuration to select the correct website or content
