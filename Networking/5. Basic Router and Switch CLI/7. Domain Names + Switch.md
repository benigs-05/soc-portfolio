# Setting the domain name, name server, and name lookup
In the router, whenever we mistype something it sometimes treats it as a hostname and attempts to resolve it as a hostname. 
The output indicates that the router is trying to DNS lookup by using the broadcast address because no specific DNS was configured.

<img width="562" height="50" alt="image" src="https://github.com/user-attachments/assets/c1adda83-22e2-431a-aa7b-abf899d13a88" />

<img width="684" height="497" alt="image" src="https://github.com/user-attachments/assets/d95740c9-98be-440d-aee0-18a8a358fbba" />

We can check our configuration and by default it won't have a domain name configured. 

We can configure it by using

`ip domain name {domain}` -> This tells our router **WHAT DOMAIN TO USE WHENEVER IT'S RESOLVING A SHORT HOSTNAME**, so it appends a domain to the **shortname given**

<img width="667" height="90" alt="image" src="https://github.com/user-attachments/assets/08d9dc16-3e10-4c82-b2d0-4ada82a1815f" />
- After configuring the domain to cmpany.com, router may append company.com to file = **file.company.com**
- But since I still haven't configured my name-server it doesn't know the address and does a broadcast instead

`ip name-server {ip address}` -> This tells our router **WHICH DNS SERVER SHOULD I ASK TO TRANSLATE THE HOSTNAME TO AN IP**
<img width="513" height="47" alt="image" src="https://github.com/user-attachments/assets/f6cfeb43-3c8e-4c5d-9024-8afba4d7169f" />

After the IP was specified it now points to the IP address of the DNS server and tries to resolve it. 
- If we had a host with file, it would've successfully resolved and would **attempt to establish a Telnet connection to it**.
- A login prompt will be used

**How do we disable the lookup?**
- `no ip domain-lookup` -> now when this is configured, anything that the router doesn't recognize as a command and would've tried to resolve to a hostname before, it won't do a lookup
- <img width="688" height="440" alt="image" src="https://github.com/user-attachments/assets/9f0595a3-4a39-4708-9547-572995ebf562" />
- To enable it we can just use `ip domain-lookup`

# SWITCHES
- When it comes to switch's CLI it's basically the same with the Router. The only difference is that the Switch is a layer 2 so it's commands will be focused on managing and viewing Layer 2 configurations
- We can still enter Privileged EXEC Mode, Global configuration Mode
- Disable lookup
- Configure hostname, secret, date, time, history size
- Configure duplex, description,
- `show ip int brief` -> will show us our interfaces along with if it's down or not
- `show mac-address-table` -> gives us our MAC address table wich shows which devices **are currently registered**
- Since the switch has multiple ports, we can manage it by using the range command `int range {interfaces}`
  - We can use this to disable or configure multiple ports. Disabling it is  hardening technique for security measures. 
- We can also save, and view our configurations
