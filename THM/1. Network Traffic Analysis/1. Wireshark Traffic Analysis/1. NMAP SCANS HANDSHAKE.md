This module helped me understand a bit of how an nmap scan might show in a packet capture. 
With TCP Full Connect it shows a fully established connection that is then droppen if there is an open port and fi it's a closed port it the server responds with the rst, ack flag. 
Although window size isn't fixed for a scan, in this module. It gave me insight wherein TCP scan's windows size > 1024 that's why i could narrow down all the client that initiated a connection with 

tcp.flags == 2 and tcp.window_size > 1024

For a TCP half scan, the client was only interested in sending in a syn, flag and immediately terminating it once it has received a syn, ack, and usually it has a window size that is less than or greater than 1024, to narrow down the packets i used 

tcp. flags == 2 and tcp.window_size <= 1024 

While for UDP scans, these are inherently harder to notice in a full packet capture since they require no handshake. But once a packet has been sent to a destination port that is closed, it usually replies with an ICMP Type 3 (Destination Unreachable) Code 3 (Port Unreachable). 

But this doesn't necessarily mean that all ICMP Type 3 Code 3 responses are scans, these can be generated by a lot of legit processes. We can narrow it down by looking at suspicious activity wherein a single host is trying to access a lot of UDP ports or many hosts, and wit no normal context of why it happened.
