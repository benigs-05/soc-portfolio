
One of the most popular initial access method is: 
	An exposed SSH, since nearly every internet-facing linux machine has SSH enabled 


# Initial Access Via SSH 
Can be accessed in two ways: 
1. Stolen key 
	1. Access a source code where private SSH keys have been stored 
	2. Data stealers by infecting an admin's laptop
2. Breached password 
	1. Weak password 
	2. Exposes an old, insecure SSH server to the internet 

cat /var/log/auth.log | grep "sshd" | grep "user"
	Presence of public key means SSH key was used and not password 


# SSH Breach example 
1. Enables SSH
2. Allows password based 
3. Sets weak password 
This can lead to brute-forcing 

# Detecting SSH attacks 
- Easy as searching for the type of logon (Failed|Accepted)

 ```
 cat /var/log/auth.log | grep "Failed" or grep "Accepted"
 ```
Again, can vary in different organizations 

Once we have our logs we can check for:
1. Username, Time, IP 
2. Check IP if malicious or not, specially if it's public IP 
3. Login history, did brute force happen before login? 
4. Is the login suspicious? Should I analyze user actions?
