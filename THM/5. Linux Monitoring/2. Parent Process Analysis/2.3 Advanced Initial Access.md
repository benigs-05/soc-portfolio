# Human-Led Attacks 
- Since Linux servers are managed by technical people, social engineering barely work on these technical people but some risks still might pose, like: 
1. A fix found in a forum, with the fix being malware
2. A developer wants to install a package but mistypes one letter (typosquatting)


# Supply Chain Compromise 
- Infects a software and infects all of its users with a malicious update since a Linux server uses hundreds of dependencies, the attack can come from anywhere


# Detecting Attacks 
- Initial Access can be uncovered via a tree process analysis. 

1.  You start with a trigger in SIEM, suspicious command or a connection
2. From there you trace which application or user initiated the events
	1. Might be a web server 
	2. Internal application
	3. IT Admin's SSH session
3. And then that's when you determine if the activity is legitimate or malicious 


So you ask, why did this specific parent run this command? Is it legitimate and expected or is it a compromise?
