# Security Log Authentication (4624/4625)

Successful Logon 4624 in relation to RDP attacks (Noisy, a lot of these logs)
Failed Logon 4625 - brute forcing, spraying, scanning (Can trick into wrong understanding of events)



Logon type 3 and 10 (RDP)

Many attempted logins, specially 4625 

If NTL is enabled for a 4624 Type 10, it usually has a preceding logon type 3 first 
2 steps: 
1.  Logon Type 3
	1. NLA authenticates first 
	2. Contains Source info
	3. Real client/workstation name/src IP 
2. Logon Type 10 
	1. The actual RDP session
	2. Confirms user got an interactive Remote Desktop Session 
	3. May not show the original workstation 

But they have different Logon ID 
Check: 
1. Same account 
2. Close timestamp
3. Same source IP 
4. Target Host 

# User Management 


1. **4720:** A new **local or domain user account was created**.
2. **4732:** An existing account was **added as a member of a security-enabled local group**.

Structure of User Management Events 
1. Subject - Account doing the action 
2. Object - The target of the action
3. Details - For security groups / new user attributes like full name or password expiration 



Red flags for 4720, account creation and 4732 security group addition 
1. No one in department can confirm action
2. Out-of-cycle logging
3. Subject's username is unknown or unexpected
4. Username doesn't follow a usual naming pattern
